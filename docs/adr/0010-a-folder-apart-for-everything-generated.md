# ADR-0010: A folder apart for everything NumericOS generates about a project

- Status: accepted (2026-10-13)
- Decider: project owner (the rule), implementation (how)

## Context

The owner: every file generated by NumericOS must be in a folder apart; it is fundamental that
the repository of a project does not get dirty.

What was true before this record, checked on the owner's own project: NumericOS itself wrote
nothing into a project's directory. Its state (documents, comments, plan, runs, the logs of
agent turns) lives in the data directory, `~/.numericos`. The risk was the agent: in `edit` or
`full` mode it may create files anywhere in the repository (helper scripts, notes, outputs of
commands), and tools it runs leave caches next to the sources.

## Decisions

1. **Each project has one NumericOS folder**, the only place where NumericOS and its agent
   put what they generate about it. By default it is `.numericos/` at the top of the project
   directory. With `NUMERICOS_WORKSPACE_ROOT` set it is `<that directory>/<project id>/`,
   outside the project altogether; the agent is then given the folder with `--add-dir`.

2. **Inside the project it ignores itself for Git.** Its own `.gitignore` holds `*`, so
   nothing in it shows in `git status` and nothing of it can be committed by accident. No
   file of the project is changed for that, and nothing under `.git`. The folder is not a
   file of the project either: it is neither listed on the Files page nor described.

3. **What it holds:** `scratch/` (what the agent creates that is not a change to the project),
   `docs/` (the theory, the notes of the plan and the description of each file as Markdown,
   rewritten when they change), `moved/` (files moved out of the repository, see 6),
   `cache/` (caches of tools the agent runs). A `README.md` in it says so.

4. **The agent is told on every turn**, after what it is told about its permissions: where
   the folder is; that anything it creates that is not itself a change to the project that
   was asked for goes under `scratch/`, never elsewhere in the repository; that it leaves no
   caches behind; that it says in its answer what it put there. A turn that writes a document
   from the project (theory, file descriptions, plan) is told instead to leave the folder
   alone: an earlier theory would be copied into the new one. Its process finds the folder in
   `NUMERICOS_WORKSPACE` and `NUMERICOS_SCRATCH_DIR`, and `PYTHONPYCACHEPREFIX`,
   `MYPY_CACHE_DIR` and `RUFF_CACHE_DIR` point into `cache/`.

5. **An instruction is not a guarantee, so the repository is watched.** Before a turn that
   may write, the supervisor notes the untracked files of the repository; when the turn ends
   it notes them again. What is new is what the turn left behind, however it was created (a
   Write tool, a shell redirection, a program the agent ran), and is recorded on the answer
   (`files_created`). What went to the NumericOS folder is ignored by Git and is not among
   them. The answer names those files.

6. **One click moves them out**: to `moved/<message id>/<same relative path>` in the folder.
   Only files that turn created, that are still there and that Git still does not track are
   moved; a file committed since is the project's own. Nothing is moved by itself: a new file
   may be exactly the change that was asked for (a new module), and only the researcher knows.

7. **Two deliberate exceptions to "NumericOS only reads the repository" (ADR-0005):** creating
   the self-ignoring folder inside the project directory, and the explicit move of decision 6.
   NumericOS still never checks out, resets, commits or changes a tracked file by itself; the
   agent changes project files only where the researcher asked for a change.

## Consequences

- Tried with the real agent in `full` mode on a small repository: asked to check something
  numerically, it wrote its script, and a virtual environment for it, under
  `.numericos/scratch/`. One file was left in the repository: `__pycache__/` of the project's
  own module, written by a Python it had started in isolated mode (which ignores
  `PYTHONPYCACHEPREFIX`). That is the case decision 5 exists for: the file is named on the
  answer and moved with one click.
- A file that appears in the repository during a turn for another reason (the researcher
  saving a new file meanwhile) is listed as left by the turn. The button moves nothing by
  itself, and what it moved stays in `moved/`.
- A turn that is still running when the supervisor is replaced is still watched: the note of
  what was untracked before it is a file of the turn.
- Programs run as experiments (M3) are not covered here: an exact commit runs in an export
  in the data directory and never touches the project; a `working_tree` run executes in place
  and what the program writes next to its sources stays there.
- The documents in `docs/` are copies for reading, for other tools and for the agent's
  context. NumericOS does not read them back: the database is the record.
